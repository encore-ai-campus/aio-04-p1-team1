# API 명세서

> 기준: `app.py`에 등록된 FastAPI 라우터와 각 핸들러의 실제 동작
>
> Swagger UI: `/docs` · OpenAPI JSON: `/openapi.json`

## 0. 서비스·인증·실행 환경

| 항목 | 현재 구현 기준 |
|---|---|
| 백엔드 프레임워크 | FastAPI |
| 실행 서버 | Uvicorn |
| 인증 | Supabase Auth |
| 인증 방식 | 이메일·비밀번호 인증 후 Supabase 세션 쿠키 사용 |
| 인증 쿠키 | `compass_supabase_access`, `compass_supabase_refresh` |
| 이메일 인증 | Supabase 이메일 인증. 인증 후 `SUPABASE_EMAIL_REDIRECT_URL`로 복귀 |
| 데이터베이스 | Supabase 연결 사용 |
| 로컬 실행 | `uvicorn app:app --reload --env-file .env` |
| 배포 플랫폼 | Railway 예정 |

인증 요청은 별도 `Authorization` 헤더가 아니라 브라우저 쿠키를 사용한다. 서버는 쿠키의 토큰을 Supabase Auth에 검증하고, 확인된 회원 정보를 기준으로 보호된 API를 처리한다.

Railway 배포 시 Start Command는 `uvicorn app:app --host 0.0.0.0 --port $PORT`로 설정한다. Railway가 제공하는 `$PORT`를 사용해야 외부에서 접근할 수 있다. 배포 도메인과 HTTPS 설정은 실제 Railway 프로젝트 생성 후 확정한다.

Railway Variables에는 다음 환경변수를 등록해야 한다.

- `DATABASE_URL`
- `SUPABASE_URL`
- `SUPABASE_PUBLISHABLE_KEY`
- `SUPABASE_EMAIL_REDIRECT_URL` (Railway 배포 도메인 기준으로 설정)
- `GROQ_API_KEY` (챗봇·교육 추천 사용 시)
- `GROQ_MODEL` (선택)
- `JEV_API_KEY` (직무 적합도 외부 API 사용 시)
- `WORK24_API_KEY` (교육 데이터 수집 시)

## 1. 구분 기준

- **API**: JSON을 반환하거나 상태 코드만 반환하며, 프런트엔드가 `fetch`로 호출하는 경로
- **페이지 라우팅**: HTML을 반환하거나 다른 페이지로 리다이렉트하는 경로
- `/api` 문자열이 포함되어 있어도 HTML을 반환하면 페이지 라우팅으로 분류한다.
- 인증이 필요한 API는 로그인 세션 쿠키가 필요하다. 별도 `Authorization` 헤더를 사용하지 않는다.

## 2. 실제 API 목록

공통 사항:

- 요청·응답 본문은 JSON이다. 단, `/training_posts?data=true`는 조회 결과에 따라 JSON을 반환한다.
- 인증 API는 `compass_supabase_access`, `compass_supabase_refresh` HttpOnly 쿠키를 사용한다. 쿠키 유효 시간은 24시간이다.
- FastAPI의 요청 모델 검증 실패는 기본 `422` 응답을 사용한다.

### 2.1 회원 인증 (`/api/auth`)

| Method | Path | 인증 | 실제 동작 | 성공 응답 |
|---|---|---:|---|---|
| POST | `/api/auth/signup` | 아니오 | 회원가입 요청 및 인증 메일 발송 | `202` |
| POST | `/api/auth/signin` | 아니오 | 로그인 및 세션 쿠키 발급 | `200`, `User` |
| GET | `/api/auth/me` | 예 | 현재 로그인한 회원 조회 | `200`, `User` |
| PATCH | `/api/auth/me` | 예 | 표시 이름 수정 | `200`, `User` |
| POST | `/api/auth/signout` | 예 | 현재 세션 종료 | `204` |
| POST | `/api/auth/password` | 예 | 기존 비밀번호 확인 후 비밀번호 변경 | `200` |
| POST | `/api/auth/withdrawal` | 예 | 비밀번호 확인 후 회원 탈퇴 처리 | `200` |

#### 요청 모델

| API | 요청 필드 |
|---|---|
| `POST /api/auth/signup` | `name`(문자열, 2~30자), `email`(문자열), `password`(영문·숫자 포함 8~128자), `password_confirm`(문자열) |
| `POST /api/auth/signin` | `email`(문자열), `password`(문자열, 1~128자) |
| `PATCH /api/auth/me` | `name`(문자열, 2~30자) |
| `POST /api/auth/password` | `current_password`, `new_password`, `password_confirm` |
| `POST /api/auth/withdrawal` | `password`, `password_confirm` |

#### 응답 예시

```json
// POST /api/auth/signup (202)
{
  "email_confirmation_required": true,
  "message": "입력하신 이메일로 인증 메일을 확인해 주세요. 이메일 인증 후 로그인할 수 있습니다."
}
```

```json
// POST /api/auth/signin, GET /api/auth/me (200)
{
  "id": "회원 UUID",
  "name": "나침반",
  "email": "compass@example.com"
}
```

```json
// POST /api/auth/password (200)
{
  "password_changed": true,
  "reauthentication_required": true,
  "message": "비밀번호가 변경되었습니다. 새 비밀번호로 다시 로그인해 주세요."
}
```

### 2.2 채용공고 검색 (`/job_posts/api`)

| Method | Path | 인증 | 실제 동작 | 성공 응답 |
|---|---|---:|---|---|
| GET | `/job_posts/api/filters` | 예 | 저장된 채용공고 기준 필터 선택지 조회 | `200`, `FilterOptions` |
| GET | `/job_posts/api/jobs` | 예 | 필터·페이지별 채용공고와 저장 여부 조회 | `200`, `JobResults` |

주요 검색 파라미터는 Swagger의 `SearchFilters` 스키마를 기준으로 한다.

실제 검색 파라미터:

| 파라미터 | 타입 | 기본값 | 제한·설명 |
|---|---|---:|---|
| `q` | 문자열 | `""` | 검색어, 최대 100자 |
| `job` | 문자열 | `""` | 직무, 최대 60자 |
| `region` | 문자열 | `""` | 지역, 최대 60자 |
| `career` | 문자열 | `""` | `신입`, `경력`, `무관`, `신입·경력` |
| `employment` | 문자열 | `""` | 고용형태, 최대 40자 |
| `exclude_closed` | boolean | `true` | 마감 공고 제외 여부 |
| `sort` | 문자열 | `default` | `default`, `deadline`, `company` |
| `page` | integer | `1` | 1 이상 10000 이하 |
| `size` | integer | `8` | 1 이상 40 이하 |

`JobResults`의 응답은 `items`, `total`, `page`, `size`로 구성되며, 각 `items`에는 공고 ID·원문 URL·제목·회사명·직무·지역·경력·고용형태·마감일·저장 여부·마감 여부가 포함된다.

### 2.5 교육 추천 (`/training_match/api`)

| Method | Path | 인증 | 실제 동작 | 성공 응답 |
|---|---|---:|---|---|
| GET | `/training_match/api/context` | 예 | 추천용 공고 목록과 프로필 요약 조회 | `200`, JSON |
| POST | `/training_match/api/recommendations` | 예 | 선택 공고와 회원 조건으로 교육 추천 생성 | `200`, JSON |
| POST | `/training_match/api/skill-recommendations` | 예 | 적합도 분석에서 확인한 부족 역량으로 교육 추천 생성 | `200`, JSON |

#### 요청 모델

`POST /training_match/api/recommendations`:

| 필드 | 타입 | 기본값 | 설명 |
|---|---|---:|---|
| `job_id` | UUID | 필수 | 추천 기준 채용공고 |
| `goals` | 문자열 | `""` | 최대 300자 |
| `budget` | integer 또는 null | `null` | 0 이상 10,000,000 이하 |
| `mode` | 문자열 | `all` | `all`, `online_first`, `online_only` |

`POST /training_match/api/skill-recommendations`는 `missing_skills` 문자열 목록을 받으며, 목록은 1~200개, 각 항목은 1~200자이다.

추천 생성은 선택 공고, 프로필 조건, `GROQ_API_KEY`, 저장 교육자료가 필요하다. 조건·후보가 없으면 `422`, 자료 조회 실패는 `503`이다.

추천 API의 오류 응답은 다음과 같이 단순한 `error` 필드를 사용한다.

```json
{
  "error": "교육비·교육 방식에 맞는 교육이 없습니다. 조건을 넓혀서 다시 시도해 주세요."
}
```

#### 실제 요청·응답 모델

```json
// PUT /api/mypage/profile
{
  "target_role": "백엔드 개발자, 데이터 엔지니어"
}
```

```json
// POST /api/mypage/certifications 또는 /api/mypage/trainings
{
  "name": "자격증 또는 교육명",
  "organization": "발급기관 또는 교육기관",
  "completed_on": "2026-11-01"

```

프로필 응답은 `target_role`, `certificates`, `courses`로 구성된다. `certificates`와 `courses`의 각 항목은 `id`, `name`, `organization`, `completed_on`을 가진다.

역량 저장 요청·응답은 다음과 같다.

```json
{
  "skills": ["Python", "FastAPI"]
}
```

역량은 최대 20개이며, 각 항목은 1~30자이다. 중복 역량은 허용하지 않는다.

## 2.9 챗봇 (`/api/chatbot`)

| Method | Path | 인증 | 실제 동작 | 성공 응답 |
|---|---|---:|---|---|
| POST | `/api/chatbot/messages` | 예 | 대화 메시지를 AI에 전달하고 답변·이동 액션 반환 | `200`, JSON |

요청 모델:

```json
{
  "message": "백엔드 개발자 공고를 찾아줘",
  "history": [
    {"role": "user", "content": "취업 준비를 시작하고 싶어"},
```

## 4. Swagger와 실제 동작의 차이

- `include_in_schema=False`인 `/auth/confirmed`, `/training_posts/`, `/training_match/`도 실제로는 동작한다.
- `/training_posts?data=true`는 같은 URL이 쿼리 파라미터에 따라 JSON API로 동작하는 예외적인 구조다.
- `/job_posts/api/*`, `/training_match/api/*`는 모듈 경로 아래에 있지만 HTML이 아닌 JSON API다.
- 공고 원본 데이터 등록·삭제 API와 교육 원본 데이터 등록·삭제 API는 현재 라우터에 구현되어 있지 않다. 다만 사용자가 자신의 자격증·이수 교육을 등록하는 `/api/mypage/certifications`, `/api/mypage/trainings`는 구현되어 있다.

## 5. 현재 구현된 오류 응답

현재 애플리케이션은 모든 API가 하나의 공통 오류 JSON 형식을 사용하지 않는다. 구현된 응답은 다음과 같다.

- FastAPI 요청 모델 검증 실패: 기본 형식의 `422` 응답
- `HTTPException`: `{"detail": "메시지"}` 형식
- 교육 추천·챗봇의 일부 처리 오류: `{"error": "메시지"}` 또는 `{"detail": "메시지"}` 형식
- 채용공고·교육자료 조회 실패: `503`
- 로그인 필요: `401`
- 이메일 미인증 또는 권한 문제: `403`
- 중복 이메일·상태 충돌·프로필 연결 문제: 구현 위치에 따라 `409`
- 존재하지 않는 채용공고: `404`

따라서 현재 문서에서는 구현되지 않은 통합 에러 코드나 `trace_id`를 추가하지 않고, 실제 핸들러가 반환하는 상태 코드와 응답 필드만 기준으로 기록한다.
